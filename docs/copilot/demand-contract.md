# 발주량 audited_v3 날짜 정렬과 입력 계약

기준일 2026-11-05. 현재 발주 추론은 audited_v3의 고정 XGBoost 모델을 사용하며 기존 D+3 계획을 함께 비교한다. 일별 마지막 로그가 확보된 뒤 입력 기준일로부터 달력 3일 뒤의 최종 ERP 계획량을 예측한다. D+3은 영업일 3일 뒤가 아니다. 데이터의 관측 시점과 계획표의 실제 기준일을 구분해야 한다.

## 학습 원본의 이월 보정

학습 전처리는 현재 관측일과 직전 관측일의 공통 부품을 비교한다. 공통 부품의 90% 이상에서 82개 수량 칸이 같으면 날짜 전체를 이월로 간주하고 마지막 비이월 날짜를 기준일로 추정한다. 이 규칙은 저장 시스템에 대한 확정 사실이 아니라 데이터에서 정한 보정 가정이다. 주말이라는 이유만으로 일괄 제외하지 않는다.

학습 전처리에서 기준일 이후 k일 지난 기록의 날짜 기준 D+h 계획은 원본의 D+(h+k) 열에서 읽는다. 예를 들어 하루 이월된 날짜의 D+3 계획은 원본 D+4 열에서 읽는다. 이월일의 actual_d에는 해당 날짜를 가리키는 계획 수량을 두되 actual_known=False로 표시한다. 이 값을 관측된 최종 수량이나 학습 정답으로 사용하지 않는다. 최근값·이동평균의 이력도 실제 관측된 최종 수량을 구분해 계산한다.

## CSV에 넣을 수량의 의미

CSV 필수 열은 `part_number`, `date`, `actual_d`, `plan_d3`, `plan_d4`, `plan_d5`다. **수량은 각 행의 date를 기준으로 날짜 정렬을 미리 끝낸 값이어야 한다.** plan_d3·plan_d4·plan_d5는 각각 그 행의 날짜로부터 달력 3·4·5일 뒤를 가리킨다. 원본의 저장 시각만 date로 바꾸고 수량 열을 그대로 복사하면 이 계약을 충족하지 않을 수 있다. 서비스 템플릿의 형식을 사용한다.

CSV 선택 열 carryover_days는 추정 계획 기준일에서 해당 행의 date까지 지난 0 이상의 정수 일수다. 0은 당일 갱신, 양수는 이월이다. 현재 추론 코드는 이 표시로 actual_known을 설정하지만 **원본 수량 열을 자동으로 재정렬하지 않는다.** carryover_days만 추가해 원본 날짜 문제가 해결됐다고 안내하지 않는다. 이미 날짜를 맞춘 actual_d와 계획 열을 입력해야 한다.

CSV에서 carryover_days를 생략하면 이월 여부를 구분하지 못한다. 이월 행이 포함된 자료라면 날짜를 먼저 정렬하고 carryover_days도 제공해야 한다. 이월일 actual_d는 그 날짜의 계획값이며 관측된 최종 정답이 아니다. 원본 계획 기준일을 알 수 없거나 목표 날짜에 해당하는 열이 없으면 입력을 임의 추정하지 말고 원본을 확인해야 한다.

## 입력 범위와 대체 예측

CSV는 동일 부품 1종의 3~60행이다. 날짜는 하루 한 행이며 날짜순으로 마지막 3일은 연속이어야 한다. 8일 이력을 권장한다. 수량은 결측·무한대 없이 0 이상이어야 하고, 0을 결측값으로 바꾸지 않는다. carryover_days는 결측 없는 0 이상의 정수로 입력해야 한다. 화면 사전 검사 통과가 날짜 의미의 검증이나 이월값의 유효성을 보장하지는 않는다.

Part 21·26은 동일 시각 수량 충돌로 격리되어 예측하지 않는다. 학습에 없던 신규 부품은 최근값 대체 예측으로 표시한다. CSV로 현재 모델을 재학습하지 않으며 공식 시드를 바꾸지 않는다. 결과의 target_date는 마지막 입력 date+3일이다. 재고·납기·단가·현장 SOP가 연결되지 않았으므로 출력값을 자동 발주량으로 확정하지 않는다.

## 특징과 시간 경계

학습과 추론은 demand_contract.py의 특징 생성 함수를 공유한다. 최근 3일의 수량·계획, 달력 정보, 관측된 과거 수량의 평균·편차, 같은 목표일의 계획 수정량을 사용한다. 전처리기와 모델은 고정된 학습 구간에 적합한다. 평가 정답과 예측 이후 자료를 입력 특징으로 사용하지 않는다. 연관 부품 후보는 검증된 BOM이나 실제 공동사용 관계를 뜻하지 않는다.
